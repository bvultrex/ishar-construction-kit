# Original mirrored type-20 pixels

Reconstructed graphics 1E97:04BF and shared helper 02DD alongside the normal 0482 path. The mirror flag comes from record byte +34. Source bytes remain forward ordered; destination traverses right to left. Horizontal clipping reverses the source displacement and includes the resource-width correction. The destination row stride is pitch plus visible width. Zero runs preserve transparent destination bytes and the original BX/DI results.

Native validation passed 432 fixtures per game (864 total), covering normal and mirrored output, isolated zeros and long/trailing zero runs, left/top clipping, three pitches and destination offset wrapping. Comparisons include six script registers, BX/DI, SP, pixel-write counts and full physical memory excluding CPU stack scratch. Typecheck passed. The startup record checker now admits mirrored type20, while other mirrored formats remain unsupported.

Actual sequence continuation is not yet validated: resuming the resource9 frame return passes MAIN polling and its callback, but the following selected context is skipped and the runner reaches unsupported numeric operand tag22 with next opcode188. The exported context reports BP17798 and SI256 rather than the intended LOGO:0081. This scheduling/context-selection boundary must be understood before claiming an actual mirrored LOGO frame. No state was patched to force the desired context. Private checkpoints remain outside the repository.
